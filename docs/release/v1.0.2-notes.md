# DocsMint 1.0.2 — Clearer MCP tool selection

## Highlights

MCP tool descriptions now distinguish single-document actions from
`batch_documents`. For one document, clients should normally select the
matching single-document tool. For multiple explicitly selected IDs requiring
the same placement, tag, trash, restore, or indexing action, they should use
`batch_documents`. The batch tool still accepts one ID for existing automation,
runs sequentially, and reports partial success per document.

The 22-tool catalog, all 31 underlying operations, input and output schemas,
authorization checks, SDK, CLI, prompts, resources, and self-hosted API-key
bridge are unchanged. The LobeHub tool descriptions match the released MCP
catalog. No database migration is required.

## Installation and compatibility

DocsMint Cloud uses the separate hosted endpoint at
`https://docsmint.com/mcp`. This OSS release does not change the deployed
Cloud tool descriptions or its OAuth server. Self-hosted users run their own
DocsMint API and set `HIAI_DOCS_URL` and `HIAI_DOCS_API_KEY` for the stdio
bridge:

```sh
npx --yes --package @hiai-gg/docsmint@1.0.2 docsmint-mcp
```

Existing clients retain the same tool names and request shapes. Upgrade when
you want the clearer tool-selection guidance in MCP discovery.

## Verification
