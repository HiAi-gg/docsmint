# DocsMint 0.8.9 — MCP contract quality and category scope

## Highlights

- Improved descriptions, parameter guidance, truthful effect annotations, and
  stable output schemas for the 21 MCP tools.
- Kept the implementation catalog, public `tools/list`, README, official Registry
  metadata, and LobeHub tool declarations in sync with deterministic tests.
- Exported `capabilityCatalog` from `@hiai-gg/docsmint/mcp` so hosted consumers
  can compare their tool list against the released OSS contract.
- Corrected the public type and output schema for `list_categories`: API-key
  principals receive sanitized category records without workspace permission
  fields; workspace clients retain the full category response.
- Fixed category-scoped document creation so an explicit category cannot be used
  to place a document into a folder owned by another category.
- Updated Cloud authorization references to direct clients to the hosted setup
  guide for currently supported connection methods.

## Compatibility and operations

- No database migration is required.
- Existing MCP tools keep their behavior except for the confirmed cross-category
  placement authorization fix and validation of the documented MCP input shape.
- This release updates OSS artifacts and declarations. Hosted production parity
  still depends on the separate SaaS release and deployment.

## Verification

- MCP package build and tests: 42 tests passed.
- SDK client tests: 28 tests passed; SDK and MCP typechecks passed.
- Packed package/runtime/declaration fixture passed.
- Category, editing-access, and document API regressions: 81 tests passed.
- MCP catalog validator and TDQS 0.2.0 static lint passed with 21 tools and no
  errors, warnings, or notes. Model-scored quality tiers were unavailable.
