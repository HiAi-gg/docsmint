# DocsMint 1.0.1 — Bounded MCP batch actions

## Highlights

The self-hosted stdio bridge now advertises 22 MCP tools. `batch_documents`
applies one action to 1–25 explicitly selected document IDs: move, set a
category, add or remove one tag, move to trash, restore from trash, or retry
indexing. Each result identifies its document and outcome. Operations run
sequentially through the existing API, which checks every document's workspace,
category, and permission scope. A failed item can leave earlier items changed;
authentication and rate-limit failures stop remaining calls. Permanent purge
is deliberately excluded from the batch tool.

`get_workspace_item` reads one visible folder, category, or tag by UUID. It
uses the existing protected folder getter or complete scoped category and tag
lists, so it does not add a new authorization route.

## Installation and compatibility

DocsMint Cloud uses the separate hosted endpoint at
`https://docsmint.com/mcp`; follow the [Cloud setup guide](https://docsmint.com/mcp/connect).
Self-hosted deployments run their own DocsMint API with `HIAI_DOCS_URL` and
`HIAI_DOCS_API_KEY`:

```sh
npx --yes --package @hiai-gg/docsmint@1.0.1 docsmint-mcp
```

The existing 20 compact tools and their 31 underlying operations remain
available. SDK, CLI, REST routes, prompts, resources, Docker deployment, and
self-hosted API-key authorization are unchanged. No database migration or
hosted OAuth change is required. Cloud clients see the two new tools only after
the hosted service adopts the matching package.

## Verification

Release CI validates the 22-tool runtime catalog, per-item batch routing and
error reporting, public package, MCP Registry and LobeHub metadata, scoped
authorization propagation, and stdio startup before publication.
