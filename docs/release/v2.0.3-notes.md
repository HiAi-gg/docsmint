# DocsMint OSS 2.0.3

MCP workspace selectors are now declared in each operation branch as well as at the JSON Schema root. The hosted 2.0.2 acceptance check found that an operation-based client normalizer removed workspaceId before sending the call, even though standards-based schema validation and direct MCP calls accepted it.

The fix preserves workspaceId in client-visible operation fields. It stays optional, retains UUID validation and is stripped before knowledge operations. The existing 22 tools, provider-side argument checks, grants and workspace assertion contracts are unchanged. Unrelated operation fields and unknown properties remain rejected.

Regression tests inspect every advertised operation branch and execute a selected call through branch-based field normalization. Existing client-routing closure checks remain enabled. A successful SDK release is separate from Cloud deployment and live OpenAI client acceptance; refresh existing custom MCP tools after Cloud adoption.

No database migration or permission expansion is introduced. SDK2 frontend peer and Bun1.4 requirements remain unchanged.
