# DocsMint OSS 2.0.1

## Workspace discovery and explicit MCP routing

The existing 22-tool catalog now accepts an optional UUID `workspaceId`. Hosted integrations can provide `workspaceRouting.listWorkspaces()` and `workspaceRouting.assertSelection(id)` when creating the MCP server. Use `list_workspace_structure(kind="workspaces")` to discover granted spaces, including empty ones. Hooks must return only currently authorized spaces and must verify the workspace bound to each request; they do not grant access themselves.

Routing arguments are validated and removed before document operations. An explicit selector without a host routing hook fails visibly. Existing calls without a selector remain compatible. No connection-wide mutable selected workspace is introduced.

Unselected hosted reads can return `operation` and `scopedResults`, with workspace identity, category scope and the complete original result per leg. Pagination stays inside each result; no global page or total is synthesized. Text and structured responses must describe the same scoped results. The public `createMcpScopedResult` validates this hosted envelope against the advertised MCP output contract.

## Dependency security

The OSS frontend moves to SvelteKit 3.1.0 and adapter-node 6. Zod is pinned to 4.6.7 and Happy DOM to 21.0.4 to address the production audit findings without new exceptions. The frontend configuration is passed directly to the Vite plugin and local imports use the package `#lib` alias.

No database migration is introduced. Cloud adoption and live client acceptance are separate release gates; this SDK release alone does not prove a hosted deployment.

## Upgrade requirements

The public frontend now requires SvelteKit 3.1 or newer in major 3, Svelte 5.57.1 or newer in major 5, and adapter-node 6. This is a major release because the supported frontend host peer range changes. MCP calls without workspaceId preserve their previous operation behavior. Cloud 1.2.1 already uses SvelteKit 3; adopting the SDK does not require another Cloud framework migration.

Bun 1.4.0 or newer is required for the updated lockfile and the release/runtime images. CI and containers use Bun 1.4.0 consistently.

The API documentation theme/types dependencies are aligned with patched Zod. Existing `/api/docs` and `/api/docs/json` routes are covered by an executable runtime regression test.

## PWA build correction

The generic PWA plugin now writes the worker into the SvelteKit 3 client output consumed by adapter-node. `/sw.js` includes the actual immutable client assets in its precache. The immutable 2.0.0 tag failed the mandatory browser artifact gate and was not published; this patch release reruns the full gates.
