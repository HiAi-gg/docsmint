# DocsMint 0.8.7 — Complete more document workflows through MCP

Agents can now move documents to trash, remove folders or categories, and restore
saved document content through the same scoped MCP connection used for search and editing.

## What changed

- **Four lifecycle tools:** `delete_document`, `delete_folder`, `delete_category`,
  and `restore_document_version`, expanding the catalog from 17 to 21 tools.
- **Existing access rules:** deletions require write access; category deletion
  requires full workspace access. Version restoration requires edit access.
- **Reversible document changes:** document deletion uses trash; restoration saves
  a backup of current content. Folder/category deletion preserves document content.
- **Clearer discovery:** every parameter has guidance, and tools expose read-only
  or destructive annotations for MCP clients.
- **Graph retrieval fixes:** related-document limits are honored after authorization;
  graph search query text filters and ranks authorized neighbors without model calls.
- Authentication proxy/server failures now show a network error instead of invalid credentials.

## Compatibility and upgrade

No database migration or new environment variable is required. Existing MCP tool
names remain available. Existing injected legacy clients remain accepted; new
lifecycle tools require a public `DocsClient` or the corresponding optional methods.
MCP annotations are hints, not authorization. The REST API enforces permissions.

Graph search now uses its supplied text to filter neighbors. For unfiltered
single-document traversal, use `get_related_documents`. Seed entity context is
not query-filtered. Blank/omitted query remains supported by the REST endpoint.

The release updates the OSS package and images. Hosted MCP clients receive the
new tools when their host adopts this release; publication alone does not deploy
an independently operated host.
