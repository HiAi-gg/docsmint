# DocsMint 0.8.8 — Clear Cloud and self-hosted MCP boundaries

DocsMint Cloud remains the recommended no-deployment MCP connection at
[`https://docsmint.com/mcp`](https://docsmint.com/mcp). This release aligns the
public OSS guides and catalogs with the currently advertised hosted
authorization contract, while keeping self-hosted deployments on their own API
and API key.

## What changed

- Cloud clients use hosted authorization-code OAuth with required PKCE S256.
  Current discovery advertises DCR at `/oauth/register`; CIMD is not part of the
  current Cloud contract. Access tokens last one hour, have no refresh token,
  and are bound to consented workspace, optional category, and scopes. A
  Bearer API-key fallback remains available.
- The `@hiai-gg/docsmint` stdio bridge connects to an already running DocsMint
  API with `HIAI_DOCS_URL` and `HIAI_DOCS_API_KEY`. Installing the bridge does
  not install or expose the DocsMint Cloud OAuth authorization server.
- Registry metadata now reports the implemented catalog of 21 tools,
  2 prompts, and 3 resources. Focused tests compare this metadata to the server
  catalog and check the self-hosted route contract.
- `SECURITY.md` reflects the supported 0.8.x line and current disclosure
  address. Technical authorization-protocol flaws remain reportable even when
  phishing appears in an exploit.
- Update the frontend's `devalue` dependency to 5.9.4 to address a moderate
  malformed-input denial-of-service advisory.

## Compatibility and upgrade

No database migration or API capability change is included. SDK, CLI, MCP
stdio authentication, `HIAI_DOCS_URL`, `HIAI_DOCS_API_KEY`, scoped API keys,
prompts, resources, Docker self-hosting, and the 21 current MCP tools remain
available as before. No OAuth authorization server is added to the OSS runtime.
