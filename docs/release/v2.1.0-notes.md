# DocsMint OSS 2.1.0

## Integration contract

The existing 22 tool names and operation selectors remain available. A public
catalog generator discovers the actual tools, prompts and resources through an
in-memory MCP transport and includes schemas, annotations and branch examples.
Host documentation can consume the catalog from its exact SDK dependency.

Input-schema failures now return JSON-RPC -32602 with redacted tool, branch,
expectedArgs and issue-path data. Clients should handle protocol errors as well
as tool execution errors. Authentication, authorization and business failures
retain their existing behavior. A public transport decorator recognizes only
confirmed upstream schema failures after normal SDK dispatch; it does not replace
that dispatcher or modify installed dependencies.

Text results are compact JSON copies of the validated structured result, retained
for compatibility. Detailed search explanations are opt-in via includeDiagnostics;
includeChunks remains separate. HTTP responses may use standard JSON or SSE for
legacy protocol traffic; no Mcp-Session-Id or sticky session is required.

## Self-hosted HTTP and REST

The existing stdio bridge is unchanged. `/mcp` additionally accepts scoped Bearer
keys through the API and public web origin. `/mcp/` is normalized internally. Set
MCP_HTTP_ENABLED=false to disable HTTP MCP independently of REST and stdio. Set
PUBLIC_APP_URL for absolute document links and CORS_ORIGINS for browser clients.
Requests without Origin remain available to authenticated server clients.

Documented programmatic routes are also available under `/api/v1`; legacy `/api`
routes remain. The v1 gateway does not expose administrative or browser-session
routes. The SDK accepts apiPrefix='/api/v1'; its existing default remains '/api'.
whoami and listWorkspaces discover only the credential's existing authority.
Explicit /api/whoami and /api/workspaces aliases support the unchanged SDK
default; they use the same Bearer and Origin checks as /api/v1. OSS has no native
Cloud workspace slug and does not install Cloud OAuth.

## Documents and search

Lists and cursors support effective categories, direct folders, rootOnly, tagIds
with tagMatch, literal q, half-open updatedFrom/updatedTo dates, visibility and
stable sorting. All filters apply before counting and pagination. Cursors bind
their filter and scope; next links preserve them.

Lists include up to 200 Unicode characters in preview and compatible content.
Search adds camelCase aliases while retaining snake_case fields. Explicit
category fields retain their legacy meaning; effectiveCategoryId/name describe
folder inheritance. SDK normalization uses the effective presentation.

Raw markdown export remains the default. format=json and exportDocWithMetadata
add identity, title, timestamps and authorized workspace/link metadata in one
request. Older hosts may still return plain markdown; their metadata is not
invented. Host presentation hooks run before output-schema validation.

## Operational compatibility

Cloud adoption is a separate release with its own product version, package pin
and submodule commit. No existing OAuth connection or permission grant is changed
by this OSS release. Existing migration 0049 from the accepted security work must
be applied through the owner migration workflow before upgraded hosts start.

Release acceptance must include CI, PostgreSQL and scoped live contracts, packed
consumers, browser/artifact gates and real client checks. This source document is
not proof of publication or production deployment.
